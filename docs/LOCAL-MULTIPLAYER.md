# 双人竞逐：本地与局域网

## 启动

```powershell
npm.cmd ci
npm.cmd run start:lan
```

默认尝试 4173，已占用就使用后续端口，实际地址以终端输出为准。`start:lan` 监听 `0.0.0.0`，允许局域网访问；`npm.cmd start` 仅监听本机。

1. 打开服务地址，选择「双人竞逐」，选择职业和委托，建立房间。
2. 创建者页面显示邀请编号、邀请链接和二维码。二维码仅包含房间地址，不包含任何玩家身份令牌。
3. 第二位玩家用同一局域网的手机扫码，或者打开邀请链接，选择职业加入。
4. 双方准备后开始。地图布局与委托相同，选路、PVE 和养成各自进行，可在地图上查看对方位置。
5. 双方击败本章 Boss 后进入切磋；结算后双方确认，继续下一章。第三章结算总积分。

已有单人局不会被双人局覆盖。离开双人房间可返回该地址下原来的单人档案。不同端口属于不同浏览器存储空间，旧地址下的单人存档仍保留在旧地址。

## 局域网排查

- 二维码不应指向 `127.0.0.1` 或 `localhost`，这两个地址在手机上指向手机本身。
- 自动识别取首个非回环 IPv4。多网卡、虚拟网卡或 VPN 下，请手动设置实际局域网地址：

```powershell
$env:HOST = '0.0.0.0'
$env:PORT = '4174'
$env:PUBLIC_ORIGIN = 'http://192.168.1.20:4174'
npm.cmd start
```

替换为电脑的实际地址与空闲端口。设定 `PUBLIC_ORIGIN` 时，应固定实际端口；若该端口已占用，请使用其他空闲端口，并同步更改地址。

- 两端必须能访问同一个服务地址。访客 Wi-Fi、AP 隔离、VPN 和 Windows 防火墙可能阻止连接。
- 本项目不会自动关闭防火墙或修改路由器。需要时由设备所有者允许 Node.js 在专用网络通信。
- 当前版本未部署公网；没有申请域名、创建云资源或开放公网隧道。

## 切磋规则

- 每章一次非致命切磋：胜利 3 分，平局各 1 分，落败 0 分。
- 继承自己的等级、装备、属性、技能装配、剩余冷却和本章终极技能次数。
- 使用独立训练生命，初始与上限均为角色最大生命的两倍。结束后恢复进入切磋前的 PVE 生命和理智。
- 双方编排 3 AP，锁定后不能修改。对方的队列不会下发给你；都锁定后由服务端结算。
- 按行动逐项交替执行；首回合先手由服务端随机决定，此后每回合轮换。控制阻止对应数量的行动，不退还该项行动点。
- 不允许使用物品、撤退或「消失」，物资保留给 PVE。
- 每回合 90 秒。超时未锁定者空过，已锁定者正常执行。最多 20 回合，届时比较剩余生命百分比，相同则平局。
- 冷却使用跨战斗时钟；PVP 消耗的终极次数保留，进入下一章才重置。
- PVE 的 HP 或 SAN 归零仍是永久死亡，并结束本次双人委托。切磋败北不算角色死亡。

## 数据与同步

`src/map.js`：7 层、16 节点的有向区域网，包含分叉和交汇。只可选择当前节点的出边，不能回头刷奖励或跳过 Boss。

`src/engine.js`：PVE 命令、全局战斗回合 `player.combatClock`、技能绝对可用回合 `player.cooldowns`、基础与主动闪避。

`src/duel.js`：确定性的双人切磋结算；输入为两个服务端角色快照，输出为训练状态与结果。

`rooms.mjs`：房间状态机。`lobby -> pve -> duel -> chapter` 循环三次后 `ended`。玩家的版本号独立，避免对方走一步导致自己的普通操作失效。

`http-server.mjs`：同源 JSON API，客户端约每 1.5 秒拉取状态。创建和加入返回独立随机令牌；后续操作需 Bearer 令牌、预期版本号与幂等编号。随机结果在服务端产生，客户端不能提交自己的属性、伤害或 RNG。

`src/network.js`：每标签页独立席位、同一请求安全重试、轮询、刷新续接与连接状态提示。凭据在 `sessionStorage`，目前没有账号系统；关闭标签页后不保证找回席位，请使用当前标签页继续。

房间保存在服务端 `.local/rooms.json`，串行修改并通过临时文件原子替换，重启后可继续。24 小时无状态更新的房间回收，最多 200 个。此目录和服务端代码不通过静态服务器暴露。

服务端限制请求大小、同源访问与基础频率，隐藏另一玩家令牌、队列及服务器 RNG。当前面向可信局域网原型测试，尚未进行公网压力测试、安全审计、账号绑定或多实例部署。日后上线需 HTTPS、持久卷、可信反向代理、备份与更严格的滥用保护。

二维码使用 [node-qrcode](https://github.com/soldair/node-qrcode) 生成 PNG，不依赖外部二维码网站。

## 验证

```powershell
npm.cmd test
npm.cmd run test:network
```

规则与 HTTP 测试覆盖完整三章循环、永久死亡、秘密队列、超时、重复提交、跨场冷却、连线约束、重启续接、身份校验和私有文件限制。双浏览器测试覆盖邀请、加入、各自选路、锁定结算、刷新、训练生命恢复，以及 320/390/768/1920 像素宽度的布局与交互。
