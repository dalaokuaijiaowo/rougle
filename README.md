# 灰烬事务所

黑色幽默文字冒险原型。单人在浏览器运行，双人模式由本地 Node.js 服务同步，不需要 API Key 或独立数据库。

v0.3 新增网状地图、左右属性对比、基础与主动闪避、跨战斗冷却，以及每章 Boss 后的双人积分切磋。扫码邀请见 [局域网联机说明](docs/LOCAL-MULTIPLAYER.md)。

## 启动

需要 Node.js 20 或更新版本。在项目目录执行：

```powershell
npm.cmd ci
npm.cmd start
```

浏览器打开终端输出的地址，默认 `http://127.0.0.1:4173`。端口占用时自动尝试下一个端口，最多到 4200。服务仅监听本机。

页面使用 ES Modules，需要通过本地服务打开，不能直接双击 HTML。

## 已实现的玩法

- 战士、盗贼、法师：独立初始属性、职业成长和各 9 项技能，共 27 项。
- 3 条固定委托：邪教年终冲刺、神谕系统离线、谢幕之前。
- 每局 3 章；每章 7 层、16 个网状节点，选择一条连通路径经过 7 个区域，总计 21 个。
- D20 属性检定，职业专属选项，自然 1 / 20 优先结算。
- 每回合 3 行动点，由玩家编排、调整或撤回行动，确认后结算一回合。
- 稳健、猛攻、防守三种战术；两格主动技能装配，被动自动生效，终极技能按章计次。
- 商店购买补给、武器改装与护甲加固；营地恢复资源；战斗中的物品纳入行动队列。
- 4 级成长，技能前置与等级限制，升级奖励三选一。
- HP 或 SAN 归零，本次角色永久结束；可签署新合同从 Lv.1 重新开始。
- 自动保存当前局、保存随机数状态、最近 20 份结局档案、JSON 档案导出。
- 桌面与手机布局；手机交战区提供直接可见的生命、理智与物品按钮。
- 更大、更粗的阅读字体；区域内我方属性与敌方 / 事件情报左右并排，手机端保留左右对比。
- 左右侧栏可分别收起，签约开局自动收起；收起后仍可通过顶部按钮展开。
- 15 种敌人图鉴、画像、战斗资料、搜索与筛选，跨局保存遭遇和击败次数。
- 本地合成的点击、攻击、施法、受击、治疗、购买、升级和结局音效；可静音、调音量并保存偏好。
- v1/v2 存档自动迁移至 v3，保留当前进度、资源、冷却、终极次数、随机数与永久死亡状态。
- 双人邀请房间、PNG 二维码、各自选路养成、每章 Boss 后非致命切磋、三章积分结算与服务端续接。

三条委托共享世界、章节地图及基本战斗数值；开场、调查内容、首领身份和结局不同。当前结局有普通处置与线索完整两类。累计至少 8 个线索进入该委托的完整结局。

首次进入，选择职业和委托后签约。开局另有 1 个可分配技能点，可以在「职业技能」中学习第二个技能。战士盾墙、盗贼隐身、法师护盾分别提供不同的生存能力。

## 数值规则

| 职业 | 初始 HP / SAN / 金币 | 主属性 / 副属性 | 每级 HP / SAN 增长 |
| --- | --- | --- | --- |
| 战士 | 30 / 20 / 10 | 力量 16 / 体质 14 | +4 / +1 |
| 盗贼 | 20 / 20 / 20 | 敏捷 16 / 幸运 14 | +3 / +1 |
| 法师 | 16 / 30 / 15 | 智力 16 / 意志 14 | +3 / +4 |

每次晋升，主副属性各 +1、技能点 +2，并额外三选一：主属性 +2、HP 上限 +6、SAN 上限 +6。上限增加多少，当前资源也增加多少；属性封顶 20。

升级时点是第一章首领后、第二章首领后、第三章入口。最后一次升级提前到最终首领之前，以便 Lv.4 的终极技能参与实战。这是针对原始「每个首领后升级」的原型调整。

```text
属性调整值 = floor((属性 - 10) / 2)
事件检定 = D20 + 属性调整值 + 主属性职业加成 2 + 技能加成
基础直接伤害 = 技能基础值 + 主属性调整值 + 武器值 + 等级 - 1
普通攻击基础值 = 5
最终直接伤害 = max(1, floor(基础直接伤害 × 战术 × 狂战 × 暴击) - 有效防御)
暴击倍率 = 1.5
命中率 = min(98%, 90% + 主属性调整值 × 2%)
暴击率 = max(1%, 5% + 幸运调整值 × 2%)
```

背刺的首击 / 隐身加成以及重击的高防御加成在战术乘区之前计算。持续伤害、斩杀、震爆弹造成真实伤害，不经过防御、暴击、战术乘区。

| 战术 | 直接伤害 | 敌方直接伤害 |
| --- | --- | --- |
| 稳健 | ×1.00 | ×1.00 |
| 猛攻 | ×1.25 | ×1.20 |
| 防守 | ×0.80 | ×0.65 |

| 敌人 | 第一章 HP / ATK / DEF | 第二章 HP / ATK / DEF | 第三章 HP / ATK / DEF |
| --- | --- | --- | --- |
| 普通 | 18 / 5 / 1 | 27 / 7 / 2 | 35 / 8 / 3 |
| 精英 | 25 / 6 / 1 | 36 / 8 / 2 | 47 / 10 / 3 |
| 首领 | 40 / 7 / 2 | 61 / 9 / 3 | 86 / 11 / 4 |

PVE 的顺序是：玩家编排的全部行动，随后一次敌方回应，再结算持续伤害与剩余时长。速度不改变 PVE 顺序。每三回合一次敌方重击，伤害 ×1.5；首领半血后，从下一回合起伤害额外 ×1.15。PVP 双方按队列逐项交替执行，先手每回合轮换。

| 行动 | 行动点消耗 |
| --- | --- |
| 普通攻击 | 1 AP |
| 主动闪避 | 1 AP；下一次直击闪避率 +35 个百分点，不叠加 |
| 装配的主动技能 | 2 AP |
| 手动终极技能 | 3 AP |
| 治疗针、清醒剂、震爆弹 | 1 AP |
| 撤退 | 3 AP，成功撤离；失败结算一次敌方回应 |

每回合恢复到 3 AP，未使用的点数不保留。选中行动只预约点数和物资，不扣血、不掷骰、不消耗物品；执行本回合时才消耗资源。队列可上移、下移、移除或清空；敌人提前死亡或成功逃脱时，后续行动不再执行，也不消耗后续物品。空队列也可以结束回合，仍承受敌人回应。

技能不会自动代选；主动技能依然需要先装配。同一个技能每回合只能安排一次，普攻可以重复安排。冷却 2 回合表示第 1 回合使用后最早第 3 回合再次使用。战斗外治疗物品仍可立即使用；每家商店每种物资库存为 2。持续伤害和冷却按完整回合结算，不随同回合的行动数量增加。

护盾和隐身在战斗间清空，技能冷却保留。`player.combatClock` 只在实际战斗回合推进，事件、地图移动、休息和刷新不会减少冷却。技能可用时点为绝对战斗回合，PVE 与 PVP 共用时钟。终极每项每章一次，进入下一章重置。「不屈」不是死亡后的复活，也不能阻止 SAN 归零。

基础闪避率：战士 5%、盗贼 12%、法师 8%。每级 +1 个百分点，敏捷调整值相对初始每提高 1 再 +2 个百分点，基础上限 35%。主动闪避提高下一次直击闪避率 35 个百分点，总上限 80%；不能闪避持续伤害。

## 文件与数据结构

| 文件 | 作用 |
| --- | --- |
| `src/data.js` | 三职业、27 技能、战术、物品、主线和事件配置 |
| `src/engine.js` | 纯规则引擎、命令校验、确定性随机数、战斗和事件结算 |
| `src/map.js` | 确定性网状地图、连线和路径校验 |
| `src/duel.js` | 双人切磋、秘密队列、回合与积分结果 |
| `rooms.mjs` / `http-server.mjs` | 房间状态机、身份校验、HTTP API、持久化 |
| `src/network.js` | 联机客户端、刷新续接与重复请求保护 |
| `src/enemies.js` | 与实战共享的敌人定义、图鉴数据同步 |
| `src/audio.js` | Web Audio 合成音效与音量控制 |
| `src/model.d.ts` | 配置、角色、战斗、存档和命令的 TypeScript 类型说明 |
| `src/app.js` | 页面、交互、浏览器存档及档案管理 |
| `src/style.css` | 桌面与手机布局 |
| `src/ui-v2.css` | 大字体、可收起侧栏、行动点编排和图鉴布局 |
| `src/ui-v3.css` | 左右对比、网状地图与双人房间布局 |
| `assets/` | 本原型绘制的城市场景、职业肖像和标志 |
| `vendor/` | 离线 Lucide 图标及许可证 |
| `tests/` | 规则测试、批量模拟、浏览器完整流程测试 |

引擎入口：

```js
import { newRun, dispatch } from './src/engine.js';

let state = newRun('mage', 'cult', 12345);
state = dispatch(state, { type: 'learn', id: 'barrier' });
state = dispatch(state, { type: 'choose', id: 'accept' });
state = dispatch(state, { type: 'advance', route: 'risk' });
state = dispatch(state, { type: 'stance', id: 'guard' });
state = dispatch(state, { type: 'queueAction', action: { kind: 'skill', id: 'barrier' } });
state = dispatch(state, { type: 'queueAction', action: { kind: 'attack' } });
state = dispatch(state, { type: 'resolveRound' });
```

`dispatch` 返回新状态，不修改传入对象；非法命令抛出 `RuleError`。UI 不计算伤害。保存的 `rng` 和 `revision` 让 JSON 往返后的结算结果保持一致。

单人使用浏览器存档。双人模式由服务端各自维护两份 PVE 状态，每章首领后建立切磋状态；PVP 训练生命归零不算永久死亡，PVE 死亡仍结束双人局。房间存于 `.local/rooms.json`，网页不会暴露该文件。当前为单实例、最多两位玩家，尚未实现共同攻击同一敌人的协作 PVE。

## 验证

```powershell
npm.cmd test
npm.cmd run simulate
npm.cmd run test:browser
npm.cmd run test:ui
npm.cmd run test:network
```

规则测试与数值模拟只需要 Node.js。浏览器测试需要运行中的本地服务、Playwright、Sharp 与 Chrome；脚本优先查找项目依赖，再使用本机 Codex 捆绑依赖。其他环境可执行 `npm.cmd install --no-save playwright sharp`。支持通过 `BASE_URL` 与 `CHROME_PATH` 指定测试网址和浏览器路径。

浏览器测试会完整操作三个职业和三条主线，检查刷新续玩、升级、商店、终极技能、结局、档案导出及损坏存档回退；另外使用明确构造的低生命测试状态验证永久死亡界面。测试覆盖 320、390、768、1440、1920 像素宽度，截图输出到 `test-results/`。

新增界面测试检查侧栏开合与自动收起、行动排序与撤销、音效实际节点和音量开关、图鉴记录去重与跨局保留。浏览器要求音频由用户交互启动，因此加载页面时不自动播放声音，第一次点击后启用。

批量模拟采用预设防御构筑、营地回血、补给和护甲购买，不代表新玩家胜率。当前数值偏向易通关的原型验证，尚未做大规模玩家平衡测试。

## 原型边界

当前已实现固定主题下的网状 DAG 和局域网双人 PVP，未实现随机主题、装备随机词条、遗物、食物、追捕链、协作 PVE 或 AI 剧情。单人存档在当前浏览器地址下；双人状态在服务端，席位凭据在当前标签页。导出 JSON 用于留档和调试，尚不支持游戏内导入。没有部署公网，也没有自动更改防火墙。
